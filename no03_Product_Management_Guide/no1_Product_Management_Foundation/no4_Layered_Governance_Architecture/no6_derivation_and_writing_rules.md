# 衍生物管理與寫作規約

> G4 衍生物的同步策略、檢核器契約，以及讓文件不再腐化的寫作規則。

---

## 衍生物盤點

任何讀取層模型的東西都是衍生物。以一個典型工作區為例：

- 自動攔截工具：目錄名正則、編號字元類別如 `no[34567]_`、worktree 前綴反查
- 各 repo 說明文件：結構敘述、配對清單
- 路由 skill：層清單、連鎖表、寫作政策分派表
- 盤點命令：掃描範圍定義
- 測試 fixture：路徑樣本
- 長期記憶：路徑引用、歸屬詞

衍生物的共同特徵：只消費層模型、不擁有。擁有者只有層宣告檔。

---

## 三種同步策略

由強到弱，能用強的不用弱的：

- **生成 generate：** 腳本從宣告檔產生衍生物。正則字元類別、worktree 前綴集合、測試 fixture 路徑最適合。生成物標注勿手改
- **檢核 verify：** 衍生物仍手寫，但有測試讀宣告檔逐項比對，drift 即紅。適合 hook 邏輯這類手寫但可機器比對的東西。編號字元類別對磁碟目錄的一致性測試是首個建議掛檢核的標的
- **引用 refer：** 敘述文件不重述清單，指向宣告檔。適合說明文件、skill 敘述

策略選擇的判準：衍生物被機器讀，用生成或檢核；被人讀，用引用。最忌諱的是策略之外的做法——手寫且無檢核，靠人記得同步。重編號案例中所有漏改都發生在手寫無檢核這類。

---

## 檢核器契約

檢核器本身屬 G4，是把關一致性的樞紐。實作前先定三件事：

- **輸入：** 層宣告檔、形態宣告、註冊表，加一份衍生物清冊。清冊逐條登記目標檔案、抽取樣式、對應的宣告欄位，例如某攔截工具第幾類正則對應宣告檔的 seq 集合。清冊是宣告檔的附屬檔，與宣告檔同目錄、同 commit 維護
- **輸出兩類：** drift 報告——逐條 PASS 或 FAIL，附衍生物現值與宣告值的差異；補建待辦——依形態與註冊表算出的缺項清單
- **觸發時機：** 至少掛在結構變更 SOP 內手動跑。工作區有測試習慣時，納入既有測試套件常駐

全綠的判準：drift 報告零 FAIL、補建待辦零項。

## 寫作規約

管所有敘述性文件，目標是讓結構變更不再需要動敘述：

- **層數不入文：** `四層` `五層` 這類字樣禁止出現在現況敘述。改寫成各層或涉及層，要精確就引用宣告檔
- **決策階段除外：** 提案、需求、整合、落地四階段屬方法論本體，數量寫死無妨。工件層才禁止
- **引用層用 id：** 敘述寫 spec 層、design 層，不寫編號目錄名。目錄名只出現在真的要指路徑的地方
- **清單不複製：** 要列出所有層的地方，指向宣告檔或標注由檢核器維護
- **歷史帶標記：** 層結構變更史的唯一落點是宣告檔沿革區，敘述文件禁止結構沿革副本。產品脈絡、決策背景這類非結構歷史可留在敘述文件，但集中在帶日期的歷史區塊。批次替換工具一律排除帶日期的歷史區塊，含沿革與案例兩類
- **歸屬詞跟著 git 邊界走：** 目錄升格為獨立 git 後，位於某 git 的歸屬敘述是高風險過期點。檢核器比對歸屬詞與宣告檔的 git_boundary

---

## 變更 SOP

任何層模型變更走同一迴圈：

- 改層宣告檔，含沿革區補一條
- 跑檢核器，取得衍生物待同步清單
- 逐項同步。生成類重跑生成、檢核類改到綠、引用類通常零改動
- 全綠後配對 commit 收工

批次文字替換的紀律：

- 替換前先分類命中點：現況引用、歷史區塊、概念同名詞。只動現況引用這類
- 對調型變更如兩層互換編號，不可單向 sed。先換暫時字串再換回
- 替換後跑檢核器加全庫殘留掃描，兩者都綠才算完

---

## 漸進採用路徑

既有工作區不必一步到位，按投資報酬排序：

- 先立層宣告檔，內容忠實記錄現況。從此有了唯一清單。同步把註冊表內各產品重複的層目錄映射移除，或降級為檢核對象並標注棄用，避免宣告出現複數落點
- 把最痛的衍生物掛上檢核：正則字元類別、目錄存在性、註冊表路徑推導
- 敘述文件逐步改為引用與去層數化，碰到才改、不專案式全改
- 生成器最後上，等檢核穩定後把高頻 drift 點轉為生成

投資是否足夠的訊號：下一次結構變更時，數檢核器沒抓到的漏改。零漏改代表夠了。
