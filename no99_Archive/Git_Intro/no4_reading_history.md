# 版本故事線閱讀方法

- 開發者需要讀懂版本故事線
- 閱讀歷史可以追蹤進度
- 閱讀歷史可以理解變更

---

## GitHub 網站介面閱讀故事線

- GitHub 網站介面是最常用的閱讀工具
- 介面操作直觀方便

### 存檔點列表 Commits

- 開發者進入 GitHub 專案頁面
- 開發者點擊 Commits 連結
- 點擊後顯示該分支的存檔點列表
- 存檔點列表顯示的欄位：
    - author 顯示提交者身份
    - commit message 顯示存檔標題摘要
    - date 顯示存檔時間
    - commit hash 是 7 碼英數字短代碼
- 點擊 commit hash 開啟該次存檔詳細頁面

### 存檔點詳細變更 Diff

- 開發者點擊列表中任一筆紀錄
- 點擊後進入該次存檔的詳細頁面
- 詳細頁面用來查看修改內容
- 是確認程式變更的主要方式
- 綠色背景代表新增的程式碼
- 紅色背景代表刪除的程式碼
- 頁面精確顯示每個檔案的變更
- 變更精確到每一行

---

## 本地終端機指令閱讀 CLI

- 終端機可用指令查看歷史
- `git log`
    - 顯示詳細的歷史紀錄
- `git log --oneline --graph`
    - 精簡單行格式
    - 圖形化顯示分支演進
    - 清晰易讀
    - 比 `git log` 更實用

---

## GUI 工具閱讀

- Sourcetree、GitKraken 與 GitHub Desktop 屬於圖形化工具
- 圖形化工具的體驗最強大
- 適合瀏覽歷史與分支關係
- 分支圖清晰展示分支的開岔與合併
- 開發者點擊任一存檔點
- 即可查看該次異動
- 工具即時顯示異動內容
- 涵蓋所有檔案的變更
- 開發者需要頻繁查看歷史
- 需要頻繁查看分支關係
- GUI 工具是最高效率的選擇
