# Git 內部結構

- 本文件拆解 Git 的靜態元素
- 聚焦開發者本機的結構
- 全篇採用倉庫比喻理解各個零件

## Git 的靜態元素

- 盤點 Git 世界中的名詞與元素
- 只談靜態結構
- 不含時間軸與操作流程

### 儲存庫 Repository

- 比喻：
    - 整個倉庫園區
- 描述：
    - 儲存庫是最大外框
    - 涵蓋工作目錄
    - 工作目錄即開發者所見的檔案
    - 也涵蓋 .git 資料夾
    - .git 資料夾是管理中心
    - .git 資料夾也是儲存區
- 類型：
    - **本機儲存庫 Local Repo**
        - 開發者本機的儲存庫
        - 含 .git 也含工作目錄
    - **遠端裸儲存庫 Remote Bare Repo**
        - GitHub 上的儲存庫
        - 只含 .git 內容
        - 無工作目錄

### .git 資料夾

- 比喻：
    - 倉庫管理與倉儲中心
- 描述：
    - 儲存庫的核心
    - 包含以下所有元素

### 物件資料庫 Object Database

- 比喻：
    - 倉庫儲藏區
    - 位於 .git/objects
- 描述：
    - 存放所有貨物的地方
    - 貨物以內容的雜湊值當作 ID
- 主要貨物類型：
    - **Blob，檔案內容**
        - 最小的貨物
        - 只儲存開發者檔案的內容
        - 不包含檔名或路徑
        - 例如一箱蘋果
    - **Tree，目錄快照**
        - 貨物清單
        - 定義一個資料夾的結構
        - 內容舉例：
            - `App.js` 檔案內容是 Blob `9a3b...`
            - `css/` 資料夾清單是 Tree `5c8f...`
    - **Commit，提交快照**
        - 棧板
        - 將所有東西串起來
        - 舉例：
            - 這張棧板用 `Tree f4c1e2...` 這張清單
            - 前一張棧板是 `parent abc123...`

### 參考 References Refs

- 比喻：
    - 倉庫管理辦公室裡的指標看板
    - 大部分位於 .git/refs
- 描述：
    - 輕量級指標
    - 指向特定的 Commit 物件
- 主要指標類型：
    - **分支 Branches**
        - 例如 .git/refs/heads/main
        - 可移動的白板
        - 指向最新的進度
    - **標籤 Tags**
        - 例如 .git/refs/tags/v1.0
        - 固定不動的奇異筆標籤
        - 錨定在某個重要歷史點
    - **HEAD，當前位置**
        - .git/HEAD 檔案
        - 開發者或倉管員的指標
        - 決定目前查看哪一塊白板
        - 也就是哪個分支

### 暫存區 Staging Area Index

- 比喻：
    - 倉庫出貨暫存平台
- 描述：
    - 單一檔案
    - 位於 .git/index
    - 是一份清單
    - 記錄下一次 `commit` 的打包內容
- 位置：
    - 位於工作目錄與物件資料庫之間
    - 扮演緩衝區角色

### 工作目錄 Working Directory

- 比喻：
    - 工廠
- 描述：
    - 開發者實際編輯檔案的地方
    - 對應專案資料夾本身
    - 不包含 .git 資料夾

### 靜態總結

| 元素 | 比喻 | 實際位置本機 | 作用 |
|---|---|---|---|
| **工作目錄** | 工廠 | 專案資料夾，非 .git | 讓開發者實際編輯檔案 |
| **暫存區** | 出貨暫存平台 | .git/index 檔案 | 準備下一次要提交的清單 |
| **物件 Blob, Tree, Commit** | 貨物、清單、棧板 | .git/objects 資料夾 | 儲存所有歷史資料，永久不變 |
| **參考 Branch, Tag** | 白板、標籤 | .git/refs 資料夾 | 用人類可讀的名稱指向特定 Commit |
| **HEAD** | 倉管員或開發者的位置 | .git/HEAD 檔案 | 指向開發者目前所在的分支 |

## 專案資料夾結構範例

- 顯示工作目錄與 .git 資料夾的相對位置

```
/SuSuGiGi/ 專案根目錄，也就是儲存庫本身
|
├── .git/ Git 管理中心，隱藏資料夾
│   |
│   ├── HEAD         檔案，指向目前所在分支
│   ├── config       設定檔，含遠端 origin 網址
│   ├── index        檔案，即暫存區 Staging Area 本身
│   │
│   ├── refs/        資料夾，存放參考 Refs
│   │   ├── heads/   資料夾，存放分支指標
│   │   │   └── main   檔案，內容為 f4c1e2...，一個 Commit ID
│   │   └── tags/    資料夾，存放標籤指標
│   │       └── v1.0   檔案，內容為 abc123...，一個 Commit ID
│   │
│   └── objects/     資料夾，即物件資料庫
│       |
│       ├── f4/        資料夾，範例，存放 f4c1e2... 物件
│       │   └── c1e2...  檔案，一個鬆散物件 Loose Object
│       ├── ab/
│       │   └── c123...  檔案，內容省略
```

## 物件建立流程

- 本節為進階選讀內容
- 承接靜態元素的說明
- 說明 `git add` 的動態建立方式
- 說明 `git commit` 的動態建立方式

### git add 的內部動作

- 執行 `git add <檔案>` 時
- Git 執行兩個主要動作：
    - **製作 Blob 物件**
        - 讀取指定檔案的完整內容
        - 計算內容的雜湊值
        - 雜湊值即 SHA-1 ID
        - 例如 `9a3b...`
        - 壓縮新內容
        - 以雜湊值為名建立 Blob 物件
        - 存入 .git/objects 儲藏區
    - **更新 Index**
        - 更新 .git/index 清單檔案
        - 記錄檔名與 Blob 物件 ID 對應關係

### git commit 的內部動作

- 執行 `git commit` 時
- Git 根據暫存區內容
- 進行一連串打包作業：
    - **製作 Tree 物件**
        - 掃描整個暫存區清單
        - 建立一個或多個 Tree 物件
        - 代表專案當下的目錄結構
    - **製作 Commit 物件**
        - 建立一個 Commit 物件
        - 內容包含：
            - Tree ID 指向根 Tree 物件
            - 該 Tree 物件剛建立完成
            - Parent ID 指向前一個 Commit
            - 藉此將歷史串連起來
            - 作者提交者資訊
            - 提交訊息
    - **移動分支指標**
        - 更新目前所在分支的指標檔案
        - 例如 .git/refs/heads/main
        - 內容改為新建立的 Commit 物件 ID
