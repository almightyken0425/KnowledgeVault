# Tag & Release - 為專案建立里程碑

## 標籤 Tag 的用途

- 專案開發到重要階段
    - 例如準備發布 v1.0 版本
- 需要方法標記該時間點
- 標記對象為存檔點 Commit
- 標記需永久保留
- 目的是方便日後找到記錄
- 標籤 Tag 即為此用途而生

---

## 標籤 Tag 的定義

- 標籤 Tag 好比歷史存檔點的書籤
- 也像里程碑的旗幟
- 開發者在某個 Commit 打上 Tag
    - 例如 v1.0.0
- 等同在該時間點插上旗幟
- 這支旗幟固定不動
- 永遠指向那個特定 Commit

---

## 標籤 Tag 與分支 Branch 的差異

- 兩者用途容易混淆
- 實際用途完全不同
- 兩者差異如下
    - **分支 Branch**
        - 好比不斷延伸的公路
        - 隨新 Commit 向前移動
        - 代表進行中的開發故事線
    - **標籤 Tag**
        - 好比公路旁的固定里程碑
        - 位置固定不動
        - 錨定歷史上特定的 Commit
        - 代表已完成的時間點
        - 具有特殊意義

| 特性 | 分支 Branch | 標籤 Tag |
| :--- | :--- | :--- |
| 移動性 | 會移動 | 固定不動 |
| 用途 | 進行中的開發 | 標記已完成的版本 |
| 比喻 | 故事線、開發公路 | 里程碑、版本旗幟 |

---

## Tag 與 Release 在 GitHub 的應用

- Git 本身只提供 tag 標記功能
- GitHub 以此為基礎
- 建立更完整的機制
- 該機制稱為 Release 發布
- GitHub Release 包含以下要素
    - Git Tag
    - 發布說明 Release Notes
    - 可供下載的附加檔案
        - 例如安裝檔 .apk 或 .exe
- Release 用於對外正式發布版本
- 是主要的發布方式

---

## 產品版本的應用與追蹤

- 開發者通常不需要親自打 Tag
- 但需要知道如何閱讀 Tag 資訊
- Release 頁面的閱讀方式
    - **辨識 Releases 區塊**
        - GitHub 專案主頁設有 Releases 區塊
        - 該區塊列出所有已發布版本
    - **閱讀版本資訊**
        - 點擊進入後顯示已發布版本列表
        - 每筆 Release 通常包含下列欄位
            - 版本號 Tag name：
                - 例如 v1.0.1
            - 發布日期：
                - 記錄該版本發布的時間
            - 發布說明 Release Notes：
                - 開發團隊在此條列新增功能
                - 也條列修復的 Bug
                - 此欄位是追蹤產品迭代的關鍵來源
            - 相關的存檔點：
                - 連結到該版本對應的程式碼快照
