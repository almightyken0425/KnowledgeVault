# Git 的緣起與維護

- 開發者理解 Git 歷史。
- 因此掌握 Git 的設計哲學。

---

## 創造者: Linus Torvalds

- Git 的創造者是 Linus Torvalds。
- Linus Torvalds 同時是 Linux 核心的創造者。
- 2005 年，Linux 核心開發團隊使用 BitKeeper。
- BitKeeper 是商業版本控制系統。
- 授權出現問題。
- 開發團隊無法再免費使用 BitKeeper。
- 當時業界缺乏合適工具。
- 需求包含以下項目:
    - Linux 核心的巨量規模
    - 分散式開發
- Linus Torvalds 花費約兩週時間解決問題。
- Linus Torvalds 以 C 語言寫出 Git 原型。
- Git 的設計目標包含以下項目:
    - 速度快
    - 設計簡單
    - 支援非線性開發
        - 意指數千個平行分支
    - 完全分散式
    - 能處理大型專案，例如 Linux 核心

## 維護者

- Linus Torvalds 隨後將維護工作交給 Junio Hamano。
- Junio Hamano 自 2005 年起接任。
- 接任職位為 Git 核心維護者。
- Junio Hamano 帶領全球開源社群。
- 開源社群持續改進與維護 Git。

### 開源社群貢獻與治理

- Git 開源社群並非實體組織。
- 開源社群指所有開發者。
- 開發者透過郵件列表 Mailing List 參與。
- 郵件列表 Mailing List 為公開性質。
- 開發者的參與方式包含:
    - 討論
    - 回報問題
    - 貢獻程式碼
- 任何人可以針對 Git 原始碼提案。
- 任何人不能直接修改 Git 原始碼。
- 這套治理模式用於防止混亂。
- 治理流程包含下列環節:
    - **提案:**
        - 開發者可以提案。
        - 提案對象為功能或錯誤修復。
        - 提案的內容是程式碼變更。
        - 程式碼變更稱為修補檔 Patch。
    - **公開審查:**
        - 開發者提交修補檔至郵件列表。
        - 全球社群成員可以審查修補檔。
        - 任何人可以提出回饋:
            - 意見
            - 質疑
            - 改進建議
    - **維護者合併:**
        - 修補檔須先通過社群審查。
        - 修補檔須獲得 Junio Hamano 認可。
        - 子系統維護者也能認可修補檔。
        - 子系統維護者須獲得 Junio Hamano 信任。
        - 通過後併入 Git 官方原始碼。
- 流程確保程式碼經多方檢驗。
- 流程兼顧開放性。
- 任何人都能貢獻程式碼。
- 流程也兼顧品質控制。
- 並非任何程式碼都能進入。
- 這套機制避免混亂。

## 維護模式: 混合式的開源生態

- Git 發展不只依賴志工貢獻。
- Git 生態系由下列角色共同構成:
    - 個人
    - 企業
    - 非營利組織

### 企業贊助

- 許多科技公司深度依賴 Git。
- 科技公司投入資源確保 Git 穩定。
- 這項投入屬於策略性投資。
- 科技公司業務與 Git 發展相關。
- 贊助案例包含下列公司:
    - **Google:**
        - Junio Hamano 自 2010 年起受僱於 Google。
        - 工作內容包含 Git 開發與維護。
    - **Microsoft:**
        - Microsoft 擁有全球最大的 Git 平台 GitHub。
        - Microsoft 也是主要貢獻者。
        - Microsoft 僱用開發者貢獻程式碼。
        - 貢獻範圍包含 Git 核心。
        - 貢獻重點包含效能方面。
        - Microsoft 也透過 GitHub 推動生態系發展。

### 非營利組織支持

- **Software Freedom Conservancy SFC:**
    - Git 專案的法律與財務歸屬於 SFC。
    - SFC 是非營利組織。
    - SFC 為 Git 提供下列支持:
        - 法律顧問
        - 財務管理
        - 行政支持
    - 這些支持確保 Git 專案獨立運作。
    - 這些支持也保護 Git 的開源精神。
