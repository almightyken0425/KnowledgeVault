## 分冊軸

**一冊一個功能域，涵蓋該域的完整縱切面。** 每冊內部固定三段：資料模型、畫面、邏輯。

這個軸的目的是讓「改一個 impl 檔」通常只碰一冊。前一版按抽取批次切十二冊，混了層軸、元件軸、功能域軸三種，同一功能被切碎——改復原要翻四冊、改帳戶名稱上限要翻三冊，且跨冊產生大量換句話說的重複條。

新增檢驗點時依其功能域歸入既有分冊。真正無單一歸屬的才進橫切冊。

## 欄位定義

十欄。順序固定，不可增減。

### ID

- 格式為 `C-<域碼>-<三位流水>`
- 域碼即分冊索引表的十五個，跨冊不重號
- 前一版的 `C-` ID 與更早的 `R-` ID 皆由 git 歷史保存。三代編號互不衝突，對照見 `no5_id_migration.md`

### 斷言

一條一件事，寫使用者可見的行為，不寫函式名。

- 省略主詞。不以「系統」或「使用者」起手
- 同一概念用同一寫法。完成按鈕不可用一律寫「不可點按」，畫面底部區塊一律寫「頁尾」
- 需要區分畫面時斷言帶畫面名，例如「首頁篩選點按關閉按鈕關閉 Modal」

### 面

驗證需要看哪一層。複合面以 `+` 連接。

- `UI` 畫面可見
- `DB` 本機 sqlite 對賬
- `LOG` runtime log 對賬
- `FB` Firestore 對賬
- `實機` 需實體裝置

### 級

可測性分層，決定誰執行。

- `T1` 操作者看畫面即可判定
- `T2` 需 Claude 對賬資料層
- `T3` 需 app 之外的介入才佈置得出前置
- `T4` 手動不可測

四級是階梯，由高往低取第一個成立者：先問不可測、再問前置要不要 app 外介入、再問判定要不要看資料層。前兩問皆否而面只有 `UI` 才是 `T1`。

**非空前置本身不是 T3 依據。** 多步導覽、開編輯器、選選項、填欄位、建基本資料、殺 App 重開，都在 app 內做得到，一律不升級。判 T3 的是下列五類，前置命中任一即成立。

| 類 | 認定 | 例 |
| --- | --- | --- |
| 外部資料寫入 | 繞過 UI 改本機或雲端儲存 | `sqlite 注入未知幣別代碼`、`清空雲端後備份再查 Firestore` |
| 外部檔案 | 裝置檔案系統要先備妥或取出檔案 | `備有含超界金額列的 CSV`、`已下載說明` |
| 系統環境 | 動 app 以外的裝置設定或連線狀態 | `斷網`、`放大系統字級後進設定主頁`、面含 `實機` |
| 帳號與商店 | 需另備帳號憑證或商店狀態 | `換帳號並選清除`、`付費帳號`、`可棄用的測試帳號` |
| 時間流逝 | 需真實等待或調時鐘才到達 | `排程已有多筆未來實例`、`無變更時等冷卻過後再備份` |

免費且已登入的常用帳號是基準身分、不算佈置。付費、全新、他人、可棄用四種帳號要另備，算。

app 內的偏好設定不是系統環境。改 app 語系與偏好時區在 app 內，`系統字級`、`系統時區`、`斷網` 在 app 外。

對賬手段寫進前置欄時不看作佈置，讀寫方向定級：`改主題後對賬 sqlite` 是讀、判 `T2`；`sqlite 清空 theme 欄後重啟` 是寫、判 `T3`。

同構行為給同級。判定基準是佈置成本、不是行為複雜度——同樣要停用一個有交易的帳戶，報表側與搜尋側必須同級。

### P

- `P0` 資金流正確性與資料完整性
- `P1` 常用路徑
- `P2` 邊角

判定基準是**壞掉的後果**，與佈置成本無關。

互補的兩半給同 `P`。一條規則的正反兩面壞掉的後果相同，不得差 `P`。

與級的關係：兩欄獨立判定，可以同 `P` 不同級。同一規則的正向與反向常常佈置成本不同——驗「接受合法值」在編輯器輸入即可，驗「載入時修正集外值」要 sqlite 注入——所以級可以差、`P` 不可以。

### spec 錨

來源 spec 檔名。Spec 未載該行為時填 `—`，並登入 `no2_spec_gaps.md`。

判定 Spec 未載前必須語意對照全部三層 Spec，不可只查 screen 層、不可只靠關鍵字比對。Spec 寫串聯而 impl 寫 cascade 是已知的字面對不上案例。

### impl 錨

**只允許兩種形態。**

| 形態 | 寫法 | 用時機 |
| --- | --- | --- |
| 檔路徑 | `src/services/categoryLogic.ts` | 行為落在整個檔，或檔內多處 |
| 檔路徑加成員 | `src/services/categoryLogic.ts::createCategory` | 行為落在單一 export，或元件內具名函式 |

**禁止：** 裸符號名、目錄型路徑、QA log marker、decorator 片段、Spec 的操作名。

裸符號名是前一版反查索引失效的根因。`showUndo` 定義在 context 裡不是 top-level export，解析退回全域搜尋、命中 debug 元件，十三條核心復原行為的反查全落錯地方。

QA marker 不是行為落點，寫進前置欄描述對賬手段。

### 前置

**只寫狀態，不寫測法。** 該條可測所需的資料與環境狀態，場次分群的依據。

- 可用：`免費帳號已有 3 個帳戶`、`sqlite 注入壞 JSON 後重啟`
- 不可用：`逐頁掃 header`、`逐一切換四種頻率`。這些是怎麼測，不是測之前要有什麼

需要 log 對賬者在此欄寫明 marker，例如 `冷啟後對賬 QA BOOT resolve`。

無特殊前置填 `—`。`T4` 一律填 `不適用`。

### 不可測原因

僅 `T4` 填寫，其餘填 `—`。載明為何手動不可測，例如 `並行時序無法手動構造`、`需觀察交易邊界、無畫面判準`。

獨立成欄的理由：前一版把原因寫進前置欄，該欄混了狀態與原因兩種語意，無法機械分群編場次。

### 自動化

已被 jest 覆蓋者填測試檔與案例名，未覆蓋填 `—`。已覆蓋者退出手動場次。

寫法為 `路徑`（案例名），案例名逐字抄測試碼、不縮寫。一條檢驗點由多個案例共同覆蓋時並列多對，以頓號分隔。

案例名兩種修飾，皆不參與逐字比對：`describe` 與 `it` 都要才定位得到時以 ` · ` 串接，覆蓋範圍的補註接在 ` — ` 之後。

填寫前必須實際讀該測試檔，確認案例真的斷言了這條行為。案例名相近但斷言別的事不算覆蓋。

### 狀態

值域兩個，`現役` 或 `退場`。缺欄視為現役。

退場代表該行為已不存在，判準無從成立。退場採原地標記，列仍留在原分冊、ID 不回收，理由見 `no8_retired.md`。

退場列的效果三件：不計入任何統計分母、不進任何反查表與場次、錨與自動化欄不再要求成立。格式與斷言去重仍要通過。

只有行為真的消失才退場。措辭或機制變動而行為仍在者走改寫，那要逐條讀 impl 現碼、不屬機械修。

十五冊是唯一來源。其餘檔案的表格由分冊生成，不手抄。

生成區以標記包住，標記外的散文手寫、不動：


| 檔 | 內容 | 來源 |
| --- | --- | --- |

| `no2_spec_gaps.md` | Spec 缺口候選 | 生成自分冊 spec 錨欄 |

| `no4_impl_anchor_index.md` | impl 錨反查索引 | 生成自分冊 impl 錨欄 |
| `no5_id_migration.md` | 前一版 ID 對照表 | 凍結表，重建當下一次性產出 |
| `no6_test_to_checkpoint.md` | 測試檔到檢驗點反向索引 | 生成自分冊自動化欄 |
| `no7_scenarios.md` 場次總表與步驟表 | 手動回歸場次 | 生成自分冊，成員資格另存 |
| `no8_retired.md` | 退場登記 | 生成自分冊與退場理由檔 |

兩份資料無法自分冊推導，各自另存：

- `no7_scenarios.data.json` 場次成員資格——哪一場、第幾步、對應哪條檢驗點
- `no8_retirement.data.json` 退場理由與後繼——理由文字長，塞進分冊表格會讓每列多兩欄破折號

其餘欄位全部推導。步驟文字取自斷言欄，⏸ 由面欄推導，進場資格由自動化欄與級欄推導，退場登記的斷言與分冊自分冊取。

改斷言只改分冊一處，跑生成即同步。手改生成區會被自檢擋下。

批次改分冊走 `apply-fixes` 子指令與指令檔，不手改。指令檔進版控，之後問「這條為什麼退場」查得到。

## 機械自檢

七項，由 `no2_qa_tools/bin/checklist.mjs` 執行。任一項不過回非零退出碼。

```bash
node no2_qa_tools/bin/checklist.mjs check --impl-root <impl git 根目錄> --spec-dir <spec 目錄>
```

| 項 | 驗什麼 |
| --- | --- |
| 格式 | 每列十欄齊備，`面` `級` `P` 三欄值域合法，ID 無重號，T4 的不可測原因非空 |
| 斷言去重 | 無完全相同、無去標點後相同 |
| Spec 覆蓋 | 每份 Spec 至少被一條檢驗點引用 |
| impl 錨 | 兩形態之一，路徑存在，成員非空時在該檔內找得到 |
| 自動化欄 | 每對測試檔與案例名：檔存在，案例名逐字可尋 |
| 零錨 impl 檔 | impl 有、清單零錨的檔。待補清單，不算不過 |
| 生成物同步 | 落檔的生成區內容等於重新生成 |

自動化欄那項的案例名比對規則：剝掉 ` — ` 之後的補註、再依 ` · ` 拆段，每段逐字比對；測試碼的單引號逃逸比對前還原。這是字串級保證，證明不了該案例真的斷言了那條行為。

### 提交閘門

`check --gate` 供 pre-commit 用。格式、斷言去重、生成物同步三項零容忍；已知未跟進的漂移走 `no2_qa_tools/rules/check_baseline.json` 的債務基準，在基準內放行、超過就擋。債務只准變少。

```bash
sh no2_qa_tools/hooks/install.sh
```
